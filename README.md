# A 股盘后市场面板

每个交易日收盘后生成**一个单文件 HTML**，几秒钟内回答四个问题（顺序也是页面顺序）：

1. **流动性**：市场里的钱在变多还是变少（国内资金面、宏观价格、政策工具；外围美元流动性只作参考）
2. **板块流向**：钱往哪些板块去、从哪些板块走
3. **国家队还在不在**：宽基 ETF 的净申赎、成交指纹，加上政策工具表佐证
4. **散户情绪**：韭菜浓度、市场体温

页面是一个带标签页的看板，打开直接看当天数据，不是宣传页：顶部固定栏有标题、交易日、更新时间和五个标签（总览 · 流动性 · 板块流向 · 国家队 · 散户情绪，标签旁的小圆点是该问题的结论色）。「总览」= 大盘指数条 + 四张卡片（每个问题一张：规则生成的结论、三个关键数、一条走势或流入流出前三，点「查看详情」进入对应标签）；每个标签页是该问题的完整明细。标签用 `#home` `#liquidity` `#sector` `#team` `#retail` 切换，图表在标签首次打开时才绘制；数据告警、板块口径、尾盘来源等放在页脚。数据源是 tushare + FRED，没有数据库、没有后台服务。
设计依据见 `docs/superpowers/specs/2026-11-06-market-dashboard-design.md`（与 `docs/reference/PROMPT.md` 冲突时以前者为准）。

## 运行

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
export TUSHARE_TOKEN=你的token          # 只从环境变量读取，不会写进日志或页面
export FRED_API_KEY=你的key             # 可选；没有则退回 FRED 公开 CSV
.venv/bin/python build.py               # 默认输出 site/index.html，交易日按北京时间当天自动回退
```

```
python build.py [--date YYYYMMDD] [--out site/index.html] [--round-start YYYYMMDD] [--demo]
```

| 参数 | 说明 |
|---|---|
| `--date` | 目标日期，缺省为北京时间当天。非交易日、或当天日线还没出，自动回退到「日线有数据的最近交易日」（最多回看 3 个开市日） |
| `--out` | 输出路径 |
| `--round-start` | 国家队「本轮」起点，缺省为交易日往前 38 个自然日 |
| `--demo` | 随机模拟数据，页面顶部有红色横幅「当前为随机模拟数据」；不访问任何网络 |

- 日志用 `logging`：INFO 打印结果，WARNING 记录缺失数据与降级；所有 WARNING 会汇总进页面数据 `meta.warnings`。
- 任何单个数据源或面板失败，只在对应位置显示「无数据 / 待披露 / 无分钟数据」，整页不崩，退出码仍为 0。
- **整体取数失败是唯一的致命情况**：交易日历取不到，或候选开市日的全市场日线全为空（典型：token 无效、tushare 整体不可用）→ 记 ERROR、**退出码 3、不写输出文件**；tushare 返回含 `token` 的错误（如「token不对」）立即失败、不重试。CI 因此不会部署，Pages 上保留上一份好页面。（`2` = 数据源初始化失败，如缺 `TUSHARE_TOKEN`，同样不写文件。）
- 「交易日回退」（当天日线还没出，退到上一个开市日）若发生在预期内（开市日 17:00 前，或 `--date` 不是开市日），只记 INFO，不进页面的警告列表；其余情况记 WARNING。
- 总览卡片里的板块流向、韭菜浓度若不是交易日 D 当天的数据，卡片上会标「（截至 M/D）」；浓度不是 D 当天时，六维体温留空。大盘条里个别指数日期晚于 D 时，指数下方有「截至 M/D」小标。
- 新闻时间线区分三种状态：取数失败 →「新闻取数失败（接口配额或错误），稍后自动重试」；只取到一部分 →「仅覆盖 M/D HH:MM 起」；取完但无匹配 →「近 7 日无匹配新闻」（payload 里是 `news.status` = `failed` / `partial` / `ok` 与 `news.since`）。
- 缺失值保持空值，**绝不补 0**，也不为了好看去填补缺失日期。
- 测试：`.venv/bin/python -m pytest -q`。
- **接口配额（本账号实测，调试时务必留意）**：
  - `stk_mins`（分钟线）：服务端提示「频率超限(1次/小时)」，且分钟数据每日 19–20 点才更新。所以尾盘占比只用**一只代表 ETF（`config.TAIL_CODE` = 510300.SH）、每次构建只调 1 次**；调用失败则显示「无分钟数据」（降级，不影响其他面板）。19 点前手动运行时取不到当天分钟数据，属正常。
  - `major_news`：「40次/天、30次/小时」。新闻按时间向前翻页（每页最多 800 行），单次构建最多调用 `config.NEWS_MAX_CALLS`（8）次，每天 3 次构建共 24 次，给手动运行留余量；用完预算、撞到配额或某页重试后仍失败，就只保留已取到的最新部分并记 WARNING，因此新闻时间线覆盖的天数取决于当天的新闻量与剩余配额。
  - 小时 / 天配额类的「频率超限」不会重试（重试没有意义）。反复调试请避免频繁完整构建。
- 在浏览器里看本机产物时，建议 `cd site && python3 -m http.server 8000` 再打开 `http://localhost:8000`。

## 部署与定时

代码公开，产物由 GitHub Actions 定时构建并发布到 GitHub Pages（`.github/workflows/build.yml`）。

**一次性设置（仓库网页上）**

1. Settings → Secrets and variables → Actions → 新增 Repository secret `TUSHARE_TOKEN`（token 只在 CI 的环境变量里，不进日志与页面）；再新增 `FRED_API_KEY`（在 https://fredaccount.stlouisfed.org 免费申请，同样不进日志与页面）。
2. Settings → Pages → Build and deployment → Source 选 **GitHub Actions**。
3. Actions 页手动点一次 `build`（`workflow_dispatch`）确认成功，Pages 地址能从外网打开。

**每天一次定时运行**：每个工作日北京时间 **21:30**（cron `30 13 * * 1-5`，UTC）。晚于原来的 20:30，是因为筹码数据（`cyq_perf`）每天 20–21 点才更新。此时日线、资金流、板块流向、韭菜浓度、龙虎榜、尾盘分钟线基本都已发布。仍会晚一天的是数据源本身的节奏：两融（交易所次日才发齐）、外盘日线（布伦特、美元指数、联邦基金期货）、深交所 ETF 份额；它们显示最近可用日期，并在页脚「数据告警」里说明。想提前看可以随时在 Actions 页手动 Run workflow。

每次都是整页重建，取「数据已就绪的最新交易日」；非交易日照常跑，内容不变。GitHub cron 高峰期可能延迟十几分钟到一小时。build job 超时 30 分钟，deploy job 10 分钟；`pages: write` / `id-token: write` 只授予 deploy job。

**退出码与部署**：构建退出码 3（整体取数失败，见上文「运行」）会让 build job 失败，deploy job 不会运行，Pages 上保持上一份好页面；之后下一次定时运行会自动重试。看到 Actions 里 build 红了，先看日志里的 ERROR：多半是 token 失效或 tushare 不可用。

**每日数据存档**：每次构建成功（非演示数据）后，当天页面用到的全部数据另存为 `history/<交易日 YYYY-MM-DD>.json`，由 `github-actions[bot]` 提交回 `main`（提交信息 `data: 存档 2026-11-06`）。同一交易日再跑会覆盖成最新一版，之前的版本留在 Git 历史里。文件里 `meta.code_version` 是当时代码的提交号，以后改了规则能分清哪些天按旧规则算。存档步骤失败不影响页面发布（运行页显示黄色提示）。本地改代码前先 `git pull`，因为机器人每天会往 `main` 提交。用法：`python build.py --archive history`（`--demo` 时不存）。

**60 天无活动会停掉定时任务**：GitHub 会在公开仓库 60 天没有任何仓库活动（push、PR 等）后自动停用定时（`schedule`）工作流。每日存档提交本身算仓库活动，正常运转时不会触发；若连续多日构建失败没有存档，仍可能被停。恢复方法：仓库 Actions 页 → 左侧选 `build` → 点页面上的 **Enable workflow**（或随手提交一次改动再手动 Run workflow）。建议每个月左右有一次提交，或手动运行一次。

**launchd 兜底只在 Actions 连不上 tushare 时才需要**（海外机房 IP 被限等）：此时改为本机 macOS `launchd` 在同样三个时间运行 `build.py`，再把 `site/index.html` 推到 Pages 分支，代价是那三个时间点 Mac 需要开机联网。Actions 能正常取数就不要用这个方案。

## 各面板口径

> **韭菜浓度、市场体温、流动性投票都是本项目自定的近似口径，不声称与任何视频或第三方算法一致。** 阈值集中在 `config.py`，可自行调整。

### 页头四句结论

| 卡片 | 规则 |
|---|---|
| 流动性 | 4 个信号投票（+1 松 / 0 / −1 紧），合计 ≥ 2「偏松」、≤ −2「偏紧」、其余「中性」；信号缺失不计票并注明。副文案另给一句外围（美元净流动性 4 周变化、利率预期），外围不参与投票 |
| 板块流向 | 同花顺行业当日净额前三（流入）/ 后三（流出） |
| 国家队 | 汇金重仓 7 只 ETF 最近 3 个**已披露**交易日净申赎：3 日合计 > 0 且至少 2 日为正 →「仍在」；合计 < 0 且至少 2 日为负 →「疑似撤出」；其余「放缓」 |
| 散户情绪 | 体温（五维）+ 全市场韭菜浓度及较昨日变化 |

### 流动性

- **流动性投票**（自定口径，阈值见 `config.VOTE`）：① 全市场成交额 ÷ 前 20 日均额（> 1.10 松，< 0.90 紧）；② 两融余额近 5 个交易日变化（> +0.5% 松，< −0.5% 紧）；③ 大盘主力净流入近 5 日累计（> 0 松，< 0 紧）；④ Shibor 1W 较 20 日均值（低 5bp 以上松，高 5bp 以上紧）。页面逐项展示。
- 场内资金卡片：全市场成交额（亿元，剔除北交所）、两融余额（沪深北合计；**次日 8:30 才出前一日数据**，卡片标注数据日期）、大盘主力净流入（`moneyflow_mkt_dc`，东方财富口径，亿元）、涨停 / 跌停家数（`limit_list_d` 精确值，市场体温面板展示的涨停 / 跌停家数同口径；取不到时体温面板回退为按涨跌幅近似并记 WARNING）、龙虎榜机构席位净买入（亿元，仅取最近 5 个交易日）。
- 宏观 / 价格卡片（`liquidity.macro`，只展示、不参与投票）：Shibor 隔夜 / 1W / 1Y（1Y 作同业存单参考，`shibor`）、DR007（`repo_daily` `DR007.IB` 加权利率，%）、DR001−政策利率（bp，`DR001.IB` 加权利率减当日政策利率）、R007−DR007（bp，`R007.IB` 减 `DR007.IB`，按日对齐）、M1 同比与 M2 同比（`cn_m`，%，月度）、社融存量同比（`sf_month` 的 `stk_endval` 当月 ÷ 12 个月前 − 1，%，月度）、10 年国债期货、布伦特原油（`fx_daily` `UKOIL`）。**政策利率锚在 `config.POLICY_RATES`（生效日、利率、名称），央行调整时需手工在末尾追加一行**；某日适用利率 = 生效日 ≤ 该日的最后一行，早于第一行的日期不出值。目前为 2026-11-02 起隔夜逆回购 1.25%。
- 大类资产条（总览与流动性标签页的指数条下方，`assets`）：黄金（`sge_daily`，元/克）、原油（上海原油主力，元/桶）、10 年国债期货（元）、美债 10 年（`us_tycr`，%，变化按 bp）、美元指数（`fx_daily` `USDOLLAR`，FXCM 点位，非 DXY）、离岸人民币（`fx_daily` `USDCNH.FXCM`，元/美元，数值涨 = 人民币贬）；显示最新值与近 1 / 4 / 13 周（往前 5 / 20 / 65 个观测）变化，价格类为 %、美债为 bp。**中债收益率曲线 `yc_cb` 本账号无权限，所以「债」用 10 年国债期货价格（价格涨 = 收益率降）。**
- **10 年国债期货（`T.CFX` 主连收盘价）只是收益率的反向代理**：价格涨 = 收益率降，不是收益率本身。
- **外围 · 美元流动性**（FRED + tushare）：美联储净流动性 = WALCL − WTREGEN − RRPONTSYD，统一为十亿美元并按周对齐，展示当前值与 4 周变化；银行准备金 WRESBAL；联邦基金有效利率 DFF 与 30 天联邦基金期货隐含利率（`100 − FED30D`）比较，差 < −10bp 标「预期降息」、> +10bp 标「预期加息」，其余「预期按兵不动」（阈值是本项目的取舍）；美债 2 年 / 10 年、美元指数（`fx_daily` `USDOLLAR`，是 FXCM 美元指数、点位在 12000 上下，**不是** ICE 的 DXY）、美股三大指数。`fx_daily` 的最新一根常是刚开盘、尚未收完的残缺日线（tick 数极少），会被丢弃并记 WARNING，取前一根，所以这类卡片的日期可能比其他卡片早一天。
- 外围新增 6 张卡（FRED，只展示）：TGA 财政部账户（`WTREGEN` ÷ 1000，十亿美元）、隔夜逆回购 ON RRP（`RRPONTSYD`，十亿美元）——两者已计入净流动性，不另计分；SOFR−IORB（bp，`SOFR` 减 `IORB`，按日对齐）、NFCI 金融条件（`NFCI`，周频，负值 = 偏宽松）、美国高收益债利差（`BAMLH0A0HYM2`，%）、美债 10 年实际利率（`DFII10`，%）。
- 政策工具表：见下文「`data/policy_ops.csv` 维护方法」。
- **新闻时间线目前暂时下线**（`config.NEWS_ENABLED = False`）：构建不调用 `major_news`、页面不显示这一块，payload 里 `news.status` 为 `disabled`；以下是恢复后的行为，把开关改回 `True` 即可。
- 新闻时间线：`major_news` 最近 7 个自然日，**只留影响资金流动性的标题**，分「国内政策 / 外围」两个页签；只列标题与原文链接，**不做任何分析或判断**。规则（词表都在 `config.py`）：标题含 `NEWS_EXCLUDE`（立案、处罚、黄金、国资委等杂讯）→ 丢弃；含 `NEWS_US_MARKERS`（美国、美联储、美债、美元…）→ 外围，且须命中 `NEWS_KW_EXTERNAL`（美联储、加息 / 降息、非农、CPI、美债、美元指数、RRP 等），所以「xx 亿美元」这类金额新闻不会进来；含 `NEWS_FOREIGN_MARKERS`（英国、日本、欧元等）→ 丢弃，外围只看美国；其余 → 国内，须命中 `NEWS_KW_DOMESTIC`（互换便利、再贷款、汇金 / 平准、降准、LPR、MLF、逆回购、净投放、货币政策、特别国债、印花税等）。原油、关税、地缘、证监会、国务院、财政部这类宽泛词已不再作为关键词。地区标记是子串匹配，加词时注意别误伤（如「日央行」会命中「11月6日央行开展…」，所以没用）。同标题去重；标题同时含「互换便利 / 再贷款」且含金额数字的会打「疑似新操作 · 请核对 policy_ops.csv」标签。`major_news` 单次最多 800 行且有日 / 小时配额，代码从最新时间向前翻页并以调用次数封顶（见上文「接口配额」）。

### 流动性指数

页面只显示指数、档位、各项得分与组合标签，**不显示任何计算方法**（不出现 σ、z、标准差、权重、阈值公式）；方法只写在这里与 `docs/superpowers/specs/2026-11-07-liquidity-gauge-design.md`。计算在 `metrics_gauge.py`，常量在 `config.GAUGE*`。

- **单项得分**：利率 / 利差类（DR001−政策利率、R007−DR007、美债 10 年、高收益债利差、SOFR−IORB）取 5 个观测的差值（bp），价格类（国债期货、美元指数、USDCNH、布伦特、黄金、上海原油）取 5 个观测的对数收益；除以该项此前 250 个观测的同类变动的标准差得偏离倍数 z（少于 120 个观测无分；标准差下限：bp 类 2bp、价格类 0.1%）；得分 = clip(50 + 方向 × z × 50/3, 0, 100)。方向：指标上升代表宽松记 +1（10 年国债期货），代表收紧记 −1（其余计分项）。黄金、上海原油只算 z、不计分（页面归在「参考」）。
- **合成**：国内分 = 国内 3 项平均，外部分 = 外部项平均；一组有效项少于一半则该组无分；两组都有分时各占 50%，只有一组有分时用该组并在结论里注明数据不足；两组都无分则页面显示「数据不足」。
- **分档**：0–25 极度紧张、25–45 偏紧、45–55 中性、55–75 偏松、75–100 极度宽松（左闭右开，100 归极度宽松）。
- **日期对齐**：各项在自己的日历上算；某 A 股交易日 D 的指数取每项日期 ≤ D 的最新得分，早于 D 超过 7 个自然日视为缺失。历史（上一交易日 / 1 周 / 1 个月 / 1 年，自然日 7 / 30 / 365 往前取不晚于该日的最近交易日）用同样规则往回重算，不依赖存档。
- **换锚与换月**：5 日窗口内跨过政策利率锚「名称」变化的那一行（如 2026-11-02 由 7 天逆回购改为隔夜逆回购），DR001−政策利率该日记缺失；10 年国债期货 `T.CFX`、上海原油 `SC.INE` 主力合约（`fut_mapping`）在窗口内换月，该日也记缺失。**`config.POLICY_RATES` 央行调整政策利率时需手工追加一行。**
- **组合信号**（条件用 z，满足 ≥ 2 个算触发）：国内资金收紧（DR001−政策利率 ≥ +1、R007−DR007 ≥ +1、国债期货 ≤ −1）；外部收紧（美债 10 年、美元指数、USDCNH 均 ≥ +1 中的 ≥ 2 项）；避险（国债期货、黄金、高收益债利差均 ≥ +1 中的 ≥ 2 项）。
- **一句话结论**：有组合触发则写触发的组合与成立的条件；否则写得分偏离 50 最多的 1–2 项；各项得分都在 40–60 写「各项都在常态范围内」；某组缺项时末尾注明「（国内缺 N 项）/（外部缺 N 项）」。
- **慢变量闸门**：M1 同比连续 3 个月下降、社融存量同比连续 3 个月下降、美元净流动性 4 周累计下降超过 3%，任一成立则表盘下方多一行黄色提示，不改指数；数据缺失视为通过。
- **旧存档兼容**：没有 `liquidity_index` / `calendar` 字段的存档照常渲染（流动性页回退为旧结论卡）。
- **其他口径说明**（原页面文字，已从页面移除）：国家队页「尾盘占比」= 510300 一只 14:30 后成交 ÷ 全天；观察池天量 = 成交额 ≥ 20 日均 3 倍，或净申赎 ≥ 60 日均 5 倍且 ≥ 10 亿；每日净申赎 = Δ份额 × 当日收盘价；全市场成交额较 20 日均的倍数 = 当日 ÷ 前 20 日均；韭菜浓度 = Σ(买+卖)(小单+中单)成交额 ÷ Σ(买+卖)(全部四档)成交额 × 100，按板块内全部个股金额加权（非简单平均）。

### 到期日提醒

只提示、不影响流动性指数；日期按规则 + 交易日历推算（`expiry.py`）。A 股：股指期货 / 期权交割日 = 每月第三个周五（3、6、9、12 月标「季月」），ETF 期权到期日 = 每月第四个周三，非交易日顺延到下一交易日。美股：月度期权到期日 = 每月第三个周五，3、6、9、12 月为三巫日 / 四巫日，遇休市提前一个交易日；**休市日在 `expiry.US_HOLIDAYS` 手工维护**。总览底部「近期提醒」列出未来 5 个 A 股交易日内的日子，国家队页在当天为相关到期日时给小字注释。

### 板块资金流向

- 数据：`moneyflow_ind_ths`（同花顺 90 个行业），`net_amount` 单位亿元；净额 = 主动买入 − 主动卖出（按 tushare 文档口径）。
- 横向发散条形图：净流入前 10（红）+ 净流出前 10（绿），可切换「当日 / 近 N 日累计」，N 为实际累计的交易日数（数据不足 5 日时小于 5，payload 里是 `sector_flow.d5.days`）。

### 国家队（ETF）

- **单只 ETF 当日净申赎（亿元）= (当日份额 − 前一日份额) × 当日收盘价**，份额单位亿份（`fund_share` 原值万份）。合计用 `sum(min_count=1)`。
- **80% 披露规则**：某天成分 ETF 中已披露份额的占比 < 80%，整天标「待披露」，不当作 0、更不当作净赎回（深交所份额常晚一天披露）。
- **国家队口径统一为汇金重仓 7 只**（`config.HUIJIN_ETF`：510300、510310、510330、159919、510050、510500、512100，汇金两家主体 2025 年末直接持有最多的宽基 ETF；512100 中证 1000 于 2026-11-08 从观察池移入）：「近 3 日」判断、净申赎图、单只份额、本轮累计、月度都用这一个池子。159919 是深市，份额晚一天披露，最新一日先按沪市 6 只合计（`DISCLOSURE_MIN` = 0.8），次日重算补齐。2026-11-07 之前的存档用的是旧口径（判断用沪市 11 只、本轮累计用 29 只），看 `meta.team_pool`：缺这个字段就是旧口径；值为「汇金重仓 6 只」的是 2026-11-07 的口径（不含 512100）。
- **汇金持仓（估算）**：国家队页顶部一格 + 「汇金持仓估算」一节（payload 字段 `holdings`），只针对汇金重仓 7 只。以 `config.HUIJIN_HOLDINGS` 的 2025 年末披露份额为起点（`HUIJIN_BASE_DATE`），之后每天把该 ETF 总份额的变化全部算作汇金的申赎，逐日滚动估算持有份额（不低于 0、不超过当日总份额；起点若高于当日总份额则取总份额），再乘当日收盘价得市值。之后的定期报告用 `config.HUIJIN_CAPS` 校准：半年报的「机构投资者合计（不含联接基金）」、季报的「单一投资者持有 ≥20%」表（表里没有汇金 → 两家主体合计上限取期末总份额 × 40%）作为当日持有上限，估算滚到该日时压到不超过上限。2026 年第 3 季度报告显示，9/30 这几只 ETF 中超过 20% 的只有联接基金，汇金年末的大部分持仓今年已赎回。**新的半年报 / 季报 / 年报披露后需手工追加 `HUIJIN_CAPS`，新年报披露后更新 `HUIJIN_HOLDINGS` 和 `HUIJIN_BASE_DATE`。** 2026 年上半年这几只 ETF 份额大幅下降（如 510050 从约 566 亿份降到 63.9 亿份），而份额下降未必都是汇金赎回，所以估算误差可能较大。某只取不到份额或价格时该行为空、不计入合计，旧存档没有 `holdings` 字段时这一格和这一节都不显示。
- **观察池天量**（`config.WATCH_ETF`，24 只）：原固定 29 只里除汇金 7 只以外的 22 只宽基，加社保基金组合持有的两只可转债 ETF（511380、511180）。只在出现「天量」时提示，**不计入**「仍在 / 放缓 / 疑似撤出」判断。天量 = 成交额 ≥ 近 20 日均值 3 倍，或 |净申赎| ≥ 近 60 个已披露日均值 5 倍且 ≥ 10 亿元（申购、赎回都算；深市当日未披露时看前一交易日）。阈值在 `config.SPIKE`。总览国家队卡片多一行「观察池天量：…」，国家队标签页有明细表，payload 字段 `watch`。
- **70%—90% 的国家队归因比例（`config.ATTRIBUTION`，页面据 `round.attribution` 显示）只是假设情景，不是事实、不是公开数据**，页面上均有注明。
- 成交指纹：核心五通道 / 宽基十只 / 行业对照六只 / 全部十六只的今昨成交额对比；尾盘占比 = **510300 一只**（代表，不是核心五通道合计）14:30 之后的成交额占全天比例，来自 `stk_mins`，无权限 / 限频则显示「无分钟数据」，有数据时来源标为「stk_mins·510300」。成交降温不等于净赎回，方向要等份额回填才能确定。

### 散户情绪

- **市场体温（自定近似口径）**：最近 30 个交易日、剔除北交所的五维等权平均，每维 0–100：上涨家数占比；涨跌幅中位数（clip(50 + 中位数 × 12.5)）；涨停 /（涨停 + 跌停）（都为 0 时取 50）；量能（clip(50 + (今日成交额 ÷ 前 20 日均额 − 1) × 100)，历史不足 5 日跳过）；赚钱效应（昨日涨停股今日上涨比例）。某维度无法计算时跳过、不当 0。**五维分里的涨跌停是按涨跌幅近似判定**（ST 5%、300/301/688/689 为 20%、其余 10%，阈值再减 0.2），不是交易所的精确涨跌停名单；面板上展示的「涨停 N 家 / 跌停 M 家」则用 `limit_list_d` 精确值，所以与五维分里隐含的近似家数可能略有出入。
- **韭菜浓度（自定近似口径）** = Σ(买 + 卖)(小单 + 中单)成交额 ÷ Σ(买 + 卖)(四档)成交额，按板块内个股**金额加权**。小单 / 中单是 tushare `moneyflow` 的分档，与是否真是「散户」只是近似关系。
- 板块成分用申万 **L2 / L3** 行业名，**与关键词完全相等才算命中**（不用 L1，也不做子串匹配；先去掉「Ⅱ」「Ⅲ」）。子串匹配在真实数据上会泄漏：「白酒」会命中 L2「非白酒」（啤酒、软饮），「电池」会命中「光伏电池组件」「电池化学品」，「电力」会命中「综合电力设备商」等。「高位连板·情绪核心」是动态板块：近 5 个交易日内有过涨停的个股。无申万权限时降级为 `stock_basic.industry`（该降级口径仍为子串匹配），页头注明口径。不含港股板块（A 股 moneyflow 不覆盖）。
- **与 PROMPT 板块表的偏离**（精确匹配要求关键词是申万 L2/L3 的真实名称，2026-11-06 用 `index_member_all` 核对，原关键词有 2 个命中 0 只）：
  - 「红利权重·银行」：关键词「银行」→「国有大型银行」「股份制银行」「城商行」「农商行」（申万银行 L1 下的四个 L2，「银行」本身不是 L2/L3 名称；原子串匹配其实只命中前两类，城商行、农商行因名称里没有「银行」二字被漏掉）。
  - 「红利权重·银行」：关键词「电信服务」→「电信运营商」（申万 L3 的真实名称，属 L2「通信服务」）。
  - 其余关键词都与某个 L2/L3 名称完全相等，未改。
  - 对成分数的影响（成分总数 / 当日 moneyflow 中出现的只数）：红利权重·银行 180/172 → 210/200；消费白酒·零售 133/120 → 117/104（不再并入「非白酒」）；机器人·汽车零部件 582/572 → 556/546（不再并入「电网自动化设备」等）；锂电·新能源 287/276 → 265/254（不再并入「光伏电池组件」「电池化学品」等）；其余板块不变。
- **热门板块（浓度墙的「热」标记与动态行）**：热度在**全市场**申万 L2 / L3 行业里排（`sw_daily` + `index_classify`，排除「申万50」等非行业指数）。每个行业取最近 5 天平均成交额 ÷ 再往前 20 天平均成交额（放量倍数），以及最近 5 天涨幅连乘的累计涨幅；两项各取在全体候选中的百分位，`分数 = 0.7 × 放量百分位 + 0.3 × 涨幅百分位`（成交放大为主、涨幅为辅）。当日流通市值不足 300 亿、历史不足 25 个交易日的行业不参与。参数在 `config.HOT_SECTORS`。
  - **动态行**：按分数从高到低取前 5 个「未被固定板块覆盖」的行业（自身或其父级 L2 名称出现在固定板块的申万关键词里即算覆盖），已选行业与其父 / 子级不重复。动态行排在墙里与固定板块一起按浓度排序，图标 🔥，昨日浓度用**今天选出的同一批**行业算，保证环比可比。
  - **固定板块标「热」**：固定板块的申万关键词里任一行业（或该行业的 L3 子行业）进入全市场前 10 名，该行标「热」。
  - 页面只显示结果，不写公式；`data.concentration.hot` 是全市场前 10 名（含 `rank`、`covered`）。
- **获利盘 / 被套比例**：个股 `cyq_perf.winner_rate`（%）按 `daily_basic.circ_mv`（流通市值）加权平均，板块 = 成分股加权，全市场同理，剔除北交所、缺市值的个股；**被套 = 100 − 获利盘**。筹码数据每天 20–21 点才更新，所以构建改在 21:30；当天还没有就往前最多找 3 个开市日，日期与浓度墙日期不同时墙下方标「获利盘截至 M/D」并计入数据告警。缺数据时该列显示「—」。
- 六维 = (5 × 五维分 + 全市场浓度) ÷ 6，仅展示今日值。

## `data/policy_ops.csv` 维护方法

政策工具（如证券基金保险公司互换便利 SFISF、回购增持再贷款）的操作记录**由人工维护，脚本不会从新闻自动抽取金额写进表**。

- 列：`date,tool,amount_yi,cum_yi,url,note` — 日期、工具、本次金额（亿元）、累计金额（亿元，可空）、来源链接、备注。
- **每一行必须有来源链接**（官方公告或可核对的新闻原文）；金额、日期、工具名称不能确认的不要写。
- 文件只有表头时，页面显示「待手工补充」，而不是硬凑数据。
- 页面新闻时间线里出现「疑似新操作 · 请核对 policy_ops.csv」标签时，请对照原文核实后再手工追加一行。
- 文件缺失、编码异常或格式错误时，页面不崩，只记 WARNING。
