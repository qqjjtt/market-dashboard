# A 股盘后市场面板 · 设计文档

日期：2026-11-06
原始需求：`docs/reference/PROMPT.md`（下称 PROMPT），本文档在它的基础上做了增删，**冲突时以本文档为准**。

---

## 1. 意图

用户每天收盘后打开一个网页，**几秒钟内**回答四个问题，顺序也按这个：

1. **流动性**：市场里的钱在变多还是变少（宏观、政策、场内资金）
2. **板块流向**：钱往哪些板块去、从哪些板块走
3. **国家队还在不在**：宽基 ETF 的净申赎、成交指纹，加上政策工具（如 SFISF）的佐证
4. **散户情绪**：韭菜浓度、市场体温

美股只作为 A 股的外部参考，放在最后，篇幅小。

「一眼看懂」= 页面最上面先给四句话结论，下面才是图表细节。

## 2. 目标 / 非目标 / 反目标

**目标**
- 每个交易日自动更新，电脑和手机都能通过一个外网地址打开
- 四个问题各有一句规则生成的结论 + 支撑它的图表
- 数据缺失时局部显示「待更新 / 待披露 / 无权限」，整页不崩

**非目标（这次不做）**
- AI 生成的分析或点评（新闻只列标题，不写判断）
- 用户账号无权限的接口：`yc_cb`（中国国债收益率曲线）、`hm_detail`（游资）、`news`、`cctv_news`、`monetary_policy`、`etf_share_size`、`etf_mins`、`us_daily`（限频 1 次/小时，不用）
- 港股板块（恒生科技等）的韭菜浓度——A 股 moneyflow 不覆盖
- PROMPT 里的 `--opend` 富途分钟线降级：`stk_mins` 已可用，且云端跑不了 OpenD
- 投资建议、仓位建议

**反目标（做了等于失败）**
- 编造数字，或用模拟数据冒充真实数据
- 缺失值填 0、把未披露当作净赎回
- 为了好看填补缺失日期
- token 出现在代码、日志、HTML 或仓库任何文件里
- 把 70%–90% 国家队归因比例写成事实

## 3. 用户已决定的事

- 数据源：tushare（Python SDK，token 从环境变量 `TUSHARE_TOKEN` 读）
- 视觉：照 PROMPT 第 5 节的暖色纸面风格；用户提供的参考截图与 PROMPT 描述一致（KPI 卡 + 体温折线、浓度条表格、净申赎柱状图带三段切换、月度柱 + 成交指纹两栏）
- 无权限的数据「先不用」，不找付费替代
- 政策面：只列新闻，不做 AI 分析；SFISF 等工具「有数据更好」
- 部署：外网可访问，**接受页面公开**（知道网址的人都能看）
- 更新：每日盘后自动，用户原话「4 点」；见 §6 的三次运行方案（已向用户说明 4 点数据不全，用户未反对）

## 4. 页面结构（自上而下）

### 4.0 页头 + 四句结论条

页头：交易日 · 数据截止说明 · 生成时间（北京时间）· 板块口径 · 尾盘来源。`--demo` 时顶部红色横幅「当前为随机模拟数据」。

结论条：四张并排卡片（≤900px 两列，≤560px 一列），每张 = 标题 + 一句结论 + 一个状态色。规则如下（**规则为 Claude 的取舍，阈值放 config.py，用户可改**）：

| 卡片 | 结论生成规则 |
|---|---|
| 流动性 | 4 个信号投票，每个记 +1（松）/ 0 / −1（紧）：① 全市场成交额 ÷ 前 20 日均额（> 1.10 松，< 0.90 紧）；② 两融余额近 5 个交易日变化（> +0.5% 松，< −0.5% 紧）；③ 大盘主力净流入（moneyflow_mkt_dc.net_amount）近 5 日累计（> 0 松，< 0 紧）；④ Shibor 1W 较 20 日均值（低 5bp 以上松，高 5bp 以上紧）。合计 ≥ 2「偏松」，≤ −2「偏紧」，其余「中性」。卡片副文案列出各信号方向。信号缺失则不计票并注明。卡片第二行单独给外围一句：「外围：美元净流动性 4 周 ↑/↓ X 十亿 · 市场预期降息 / 加息 / 按兵不动」，不参与国内投票 |
| 板块流向 | 「流入：A、B、C ｜ 流出：X、Y、Z」= 同花顺行业当日净额前三 / 后三 |
| 国家队 | 取沪市 11 只核心 ETF 最近 3 个**已披露**交易日净申赎：3 日合计 > 0 且至少 2 日为正 →「仍在（近 3 日 +X 亿）」；3 日合计 < 0 且至少 2 日为负 →「疑似撤出（−X 亿）」；其余 →「放缓」。附本轮累计。最新日待披露时写明「截至 M/D」 |
| 散户情绪 | 「体温 71.2（温暖）· 浓度 65.3%（+1.2pp）」，状态色按体温色带 |

### 4.1 流动性

分「国内」与「外围」两组，外围是 A 股的参考，篇幅小于国内。

**0. 大盘涨跌条**（本节最上方一行）：上证指数、深证成指、创业板指、科创 50、沪深 300（`index_daily`：000001.SH / 399001.SZ / 399006.SZ / 000688.SH / 000300.SH）的收盘与涨跌幅，红涨绿跌。

**a. 场内资金卡片组**（每张：当前值、较前值变化、近 30 交易日 sparkline）
- 全市场成交额（亿元，剔除北交所）及 ÷ 20 日均
- 两融余额（`margin`，沪深北合计，亿元）及日变化。注意 margin 次日 8:30 才出前一日数据，卡片标注数据日期
- 大盘主力净流入（`moneyflow_mkt_dc.net_amount`，亿元）
- 活跃资金：涨停 / 跌停家数（`limit_list_d`）、龙虎榜机构席位净买入（`top_inst`，亿元）

**b. 宏观 / 价格卡片组**
- Shibor 隔夜、1W（`shibor`，%）
- M2 同比（`cn_m`，月度，标注月份）
- 10 年国债期货主连收盘（`fut_daily` + `fut_mapping`，`T.CFX`）——**收益率的代理，价格涨 = 收益率降**，卡片上写明
- 布伦特原油（`fx_daily` `UKOIL`，美元/桶，用 `bid_close`）

**c. 政策工具表**：读仓库内手工维护的 `data/policy_ops.csv`（列：日期、工具、金额亿元、累计亿元、来源链接、备注）。**脚本不从新闻自动提取金额写进表**。初始内容由实现者从 major_news 中查到的 SFISF / 回购增持再贷款操作新闻整理（新闻 url 即来源链接），每行必须有来源链接；查不到金额的不写。若整理不出可靠行，交付一张只有表头的空表 + 页面提示「待手工补充」，不硬凑。

**e. 外围 · 美元流动性与加减息**（卡片组，每张：当前值、变化、sparkline）
- 美联储净流动性 = 资产负债表 WALCL − 财政部 TGA 账户 WTREGEN − 隔夜逆回购 RRPONTSYD（单位统一为十亿美元；WALCL / WTREGEN 为百万美元周频，RRP 为十亿美元日频，按周对齐到 WALCL 日期）。展示当前值与 4 周变化
- 银行准备金 WRESBAL（周频）
- 联邦基金有效利率 DFF，与 30 天联邦基金期货隐含利率（100 − `fx_daily` `FED30D` 的 bid_close）并列；隐含 − 有效 < −10bp 标「市场预期降息」，> +10bp 标「预期加息」，其余「预期按兵不动」（阈值 config 可调，Claude 的取舍）
- 美债 2 年 / 10 年收益率（`us_tycr` y2 / y10）
- 美元指数（`fx_daily` `USDOLLAR`）
- 美股三大指数（`index_global` SPX / IXIC / DJI）
- 数据源：tushare 之外，新增 **FRED 公开 CSV**（`https://fred.stlouisfed.org/graph/fredgraph.csv?id=<序列>`，无需 key，2026-11-06 实测可用）。作为一个独立的 source 类，失败时这几张卡片显示「无数据」，不影响其他
- 各卡片标注自身数据日期（FRED 周频数据滞后数日属正常）

**d. 新闻时间线（两个页签：国内政策 / 外围）**：`major_news` 最近 7 个自然日，按关键词过滤。国内政策页签关键词（config）：互换便利、SFISF、再贷款、汇金、平准、央行、人民银行、证监会、金融监管、降准、降息、LPR、MLF、逆回购、国务院、政治局、财政部、特别国债。外围页签关键词（config）：美联储、鲍威尔、FOMC、议息、加息、降息、非农、CPI、美债、美元、欧央行、日本央行、英国央行、关税、原油、OPEC、地缘。两个页签都命中的归「国内政策」。按时间倒序，每条 = 时间 · 来源 · 标题（点击打开 `url` 字段的原文，已确认 major_news 返回 url，如 10jqka.com.cn 链接；个别为空时只显示标题）。标题同时含「互换便利 / 再贷款」且含金额数字的，打一个「疑似新操作 · 请核对 policy_ops.csv」标签。同标题去重。

> major_news 单次最多返回 800 条，一天就会超，需要按时间窗口切片拉取（如每 3 小时一段），直到每段 < 800。

### 4.2 板块资金流向（新增，PROMPT 无）

- 数据：`moneyflow_ind_ths`（同花顺 90 个行业，`net_amount` 单位亿元——实现时核对单位）
- 一个 ECharts 横向发散条形图：净流入前 10（红，向右）+ 净流出前 10（绿，向左），条旁标行业名、净额、当日涨跌幅
- 右上角两段切换：「当日」/「近 5 日累计」
- 副标题：「同花顺行业口径 · 净额 = 主动买入 − 主动卖出」（按 tushare 文档口径写准）

## 5. 技术形态

- Python 3.10+，依赖：`tushare`、`pandas`、`numpy`（本机是 3.14，CI 用 3.12 即可）
- 单文件 HTML，ECharts 5.5.0 from cdnjs，其余内联，数据 JSON 嵌入（`</` 转义、NaN → null，前端显示「—」）
- 代码结构照 PROMPT 第 6 节（config / sources / demo / metrics / template / build），新增的数据（流动性、板块流向、新闻、美股、政策表）同样走 sources → metrics → template，不另起炉灶
- `python build.py [--date] [--out] [--round-start] [--demo]`；去掉 `--opend*`
- 重试、日志、降级规则照 PROMPT 第 2 节
- 每次运行全量重新拉取所需窗口（不建数据库、不做缓存文件提交到仓库）

## 6. 部署与调度

- 新仓库 `market-dashboard`（本地路径 `~/Documents/market-dashboard`），推到用户的 GitHub 账号 `qqjjtt`，Pages 地址预计为 `https://qqjjtt.github.io/market-dashboard/`
- 本机目前没有 GitHub 凭据（无 SSH key、无 gh、git 未设 user.name）。以下由用户本人在网页上完成，实现者给出逐步清单后等待：① 新建公开仓库 `qqjjtt/market-dashboard`；② Settings → Secrets → 新增 `TUSHARE_TOKEN`；③ Settings → Pages → Source 选 GitHub Actions；④ 本机推送凭据（建议生成 SSH key 并添加到 GitHub，或用 HTTPS + Personal Access Token）。实现者不经手 token
- **GitHub Actions** 定时运行 `build.py`，产物发布到 **GitHub Pages**；`TUSHARE_TOKEN` 存在仓库 Secrets
- 免费 Pages 要求仓库公开 → **代码也是公开的**（不含 token）
- 调度（北京时间，周一至周五；cron 用 UTC）：
  - 16:30（08:30 UTC）：日线、成交指纹、外盘、新闻先出
  - 20:30（12:30 UTC）：资金流、板块流向、浓度、尾盘、沪深 300 补齐
  - 次日 09:30（01:30 UTC）：ETF 份额回填
  - 每次都是整页重建，取「数据已就绪的最新交易日」；非交易日照常跑但内容不变
  - 另留 `workflow_dispatch` 手动触发按钮
- GitHub cron 高峰期可能延迟十几分钟到一小时，可接受
- **云端可达性兜底（Claude 的取舍）**：接口探测是在本机做的，Actions 机器在海外、IP 每次不同，tushare 可能限 IP 或限频。实现的第一步就是在 Actions 上做一次冒烟测试（调 trade_cal + daily 各一次）。失败则改为：本机 macOS `launchd` 按同样三个时间运行 build.py，再把 HTML 推到 Pages 分支（代价：那三个时间点 Mac 需要开机联网）
- **限速（Claude 的取舍）**：sources 层加全局节流，默认每分钟 ≤ 200 次调用（config 可调），遇频控按 PROMPT 的退避重试
