# 提示词：用 tushare 复现「市场情绪 · ETF 资金面板」

> 用法：整段复制给本机的 Claude Code（或其他能写代码、能执行命令的 AI）。
> 需要放在能访问 api.tushare.pro 的电脑上运行，并提前 `export TUSHARE_TOKEN=...`。
> 如果你的口径和下面不同（ETF 名单、板块、归因比例），直接改「可配置项」那一节再发。

---

## 0. 角色与目标

你是一名量化工程师兼前端工程师。请用 Python + tushare 写一个**可重复运行的脚本**，每天收盘后生成一个**单文件 HTML** 面板，复现下面 5 个模块：

1. 市场体温（综合情绪分 + 30 日走势）
2. 板块「韭菜浓度」热力墙（散户成交占比，按板块排序）
3. 资金流向与指数背离（沪市核心 ETF 净申赎 vs 沪深300）
4. 固定宽基 ETF 本轮逐日净申赎（本轮累计、近 3 日、月度柱）
5. 成交指纹：谁在退、谁在进（ETF 分组成交额今昨对比 + 尾盘占比 + 自动结论）

做完后**必须用真实数据实际跑一次**，打开 HTML 截图自检，并把日志里的告警汇总给我。不要只交代码。

## 1. 运行环境与约束

- Python 3.10+，依赖只用：`tushare`、`pandas`、`numpy`；可选 `futu-api`（OpenD）
- token 只从环境变量 `TUSHARE_TOKEN` 读取，**不要写进代码、日志或 HTML**
- 前端：单个 HTML 文件，图表用 ECharts 5.5.0（`https://cdnjs.cloudflare.com/ajax/libs/echarts/5.5.0/echarts.min.js`），其余 CSS/JS 全部内联；数据以 JSON 嵌入页面
- 不引入数据库、不起 Web 服务；一条命令出一个文件
- A 股配色习惯：**红 = 涨 / 流入，绿 = 跌 / 流出**

### 命令行

```
python build.py [--date YYYYMMDD] [--out dashboard.html] [--round-start YYYYMMDD]
                [--opend] [--opend-host 127.0.0.1] [--opend-port 11111] [--demo]
```

- `--date` 缺省为今天；若非交易日，自动回退到最近交易日
- `--demo`：用随机模拟数据跑通全链路（接口与真实数据源一致），页面顶部显示醒目红色横幅「当前为随机模拟数据」
- `--opend`：尾盘分钟数据改用本机富途 OpenD

## 2. 数据源与单位（务必统一）

| 用途 | tushare 接口 | 原始单位 | 统一后 |
|---|---|---|---|
| 交易日历 | `trade_cal(exchange='SSE', is_open='1')` | — | YYYYMMDD 列表 |
| ETF 份额 | `fund_share(ts_code, start_date, end_date)` → `fd_share` | 万份 | 亿份（÷1e4） |
| ETF 日线 | `fund_daily` → `close`、`amount` | 元、千元 | 元、亿元（÷1e5） |
| ETF 名称 | `fund_basic(market='E')` | — | — |
| 对照指数 | `index_daily('000300.SH')` | 点 | 点 |
| 个股日线 | `daily(trade_date)` → `pct_chg`、`amount` | %、千元 | %、亿元 |
| 个股名称/行业 | `stock_basic(list_status='L')` | — | — |
| 个股资金流向 | `moneyflow(trade_date)` → `buy/sell_{sm,md,lg,elg}_amount` | 万元 | 保持比例即可 |
| 申万行业成分 | `index_member_all(is_new='Y')`，分页 limit=3000 | — | — |
| ETF 分钟线 | `stk_mins(freq='1min')` | 元 | — |
| 备选分钟线 | OpenD `request_history_kline(code='SH.510300', ktype=K_1M)` → `turnover` | 元 | — |

### 权限与降级（必须实现，不能整页崩）

- 每个接口调用都包重试：失败后等 2s / 4s / 8s 再试，最多 4 次；遇到频控同样处理
- `index_member_all` 无权限 → 退回 `stock_basic.industry` 做板块匹配，页面注明「板块口径：stock_basic.industry」
- `stk_mins` 无权限且未开 `--opend` → 尾盘占比显示「无分钟数据」
- 某只 ETF 取不到数据 → 日志 WARNING 列出代码并跳过，不影响其他
- 某天份额未披露（深交所常晚一天）→ 保持空值，**不填 0、不当作净赎回**；当日成分 ETF 中披露不足 80% 的，整日标记为「待披露」

## 4. 各面板口径与展示

### 4.1 市场体温

**数据**：最近 `TEMP_WINDOW + AMOUNT_MA + 2` 个交易日的全市场 `daily`，剔除北交所（`.BJ`）。

**涨停/跌停判定**（近似）：名称含 ST → 5%；代码以 300/301/688/689 开头 → 20%；其余 10%。`pct_chg ≥ 阈值 − 0.2` 记涨停，`≤ −(阈值 − 0.2)` 记跌停。

**五个维度，每个 0–100，等权平均**：

1. 上涨家数占比 = 上涨家数 / 总家数 × 100
2. 涨跌幅中位数 = clip(50 + 中位数 × 12.5, 0, 100)（±4% 对应 0/100）
3. 涨停情绪 = 涨停数 / (涨停数 + 跌停数) × 100；两者都为 0 时取 50
4. 量能 = clip(50 + (今日总成交额 / 前 20 日均额 − 1) × 100, 0, 100)；不足 5 日历史则跳过该日
5. 赚钱效应 = 昨日涨停股今日上涨的比例 × 100

**六维**：今日五维分与「全市场韭菜浓度」做 5:1 加权，仅显示今日值。

**展示**：
- 4 张 KPI 卡：
  - 今日体温（≥60 红，40–60 橙，<40 蓝），副标题「五维口径 · 六维含浓度为 X」
  - 昨日 → 今日 差值，副标题「昨 → 今 · 几乎没动 / 明显升温 / 明显降温」（|差| < 2 视为没动）
  - 30 日均值偏离，副标题「今日 X vs 均值 Y · 明显偏热 / 偏热 / 接近均值 / 偏冷 / 明显偏冷」（阈值 ±5、±15）
  - 近 30 日排名「第 N 高」，副标题「N 期中高于 P% 的交易日 · 最高 X（日期）」
- 色带图例：过热 80+ / 温暖 60–80 / 中性 40–60 / 偏冷 20–40 / 冰冷 <20
- 折线图：橙色线 + 渐变面积；30 日均值虚线；标注区间最高（红点 + 「X · 区间最高」）、区间最低（绿点 + 「日期 · X」）；今日用大号红字「今日 X」，并给最后一根加浅橙底色高亮
- 图下列出今日五个维度分项、涨停/跌停家数、样本区间与期数

### 4.2 板块韭菜浓度热力墙

**口径**：浓度 = Σ(买+卖)(小单+中单)成交额 ÷ Σ(买+卖)(全部四档)成交额 × 100，按板块内全部个股**金额加权**（不是简单平均）。昨日用同一口径、同一方法（「高位连板」板块的成员按昨日窗口重新计算）。

**展示**（HTML 表格，不用 ECharts）：
- 列：板块（图标 + 名称 + 灰色 `n=成分数`）｜浓度条（横条长度 = 今日值%，黑色竖刻度 = 昨日值）｜今日 %｜环比（百分点，红正绿负；昨日无数据显示「新增」）
- 按今日浓度降序；第一行浅红底色高亮
- 颜色按排名三等分：前 1/3 红、中 1/3 橙、后 1/3 蓝（条和数值同色）
- 表头上方说明口径，并给出全市场浓度

### 4.3 资金流向与指数背离

**口径**：单只 ETF 当日净申赎（亿元） = (当日份额 − 前一日份额)（亿份）× 当日收盘价。合计时用 `sum(min_count=1)`，并套用「80% 披露」规则。

**展示**（一个 ECharts 容器 + 右上角三段切换）：
- 「单日净申赎」（默认）：柱状图，正红负绿
- 「累计净申购」：累计折线（红，带浅色面积）+ 右轴沪深300收盘价（蓝），用来直观看「指数跌、资金反而流入」的背离
- 「单只份额」：每只 ETF 的份额折线（亿份），图例可滚动
- 副标题：「沪市 11 只核心 ETF 每日净申赎（亿元），正为流入；净申赎 = Δ份额 × 当日收盘价」

### 4.4 固定宽基本轮逐日净申赎（左栏）

- 标题：「📊 {实际取到的只数} 只固定宽基本轮逐日净申赎」
- 副标题：「{起} — {止} 累计 **+X 亿元**；按 70%—90% 归因情景，疑似国家队回补约 A—B 亿（中值 C 亿）。归因比例为假设，非公开数据。」
- 3 张单日卡片：最近 3 个交易日，从新到旧；未披露显示灰色「待披露」
- 月度柱状图：最近 6 个月的净申赎合计，正红负绿，柱顶标注带符号的整数，X 轴两行「N月 / 交易日数」
- 底注：「缺值保持空值，**不填 0，也不当卖出**」

### 4.5 成交指纹：谁在退、谁在进（右栏）

**分组**：核心五通道、宽基十只、行业对照六只、全部十六只（= 宽基十只 + 行业六只）。

**每组**：今日成交额、昨日成交额、变化 %（取整）、今/昨比值 %。

**尾盘占比**：核心五通道 14:30 之后的成交额 ÷ 全天成交额，今日与昨日都要算；来源按 stk_mins → OpenD → 无 的顺序降级。

**展示**：
- 列表：`核心五通道（5 只）  135.15 亿 · 昨 233.66（−42%）`，颜色按涨跌；最后一行显示尾盘占比
- 橙色边框结论框：左侧大字 = 宽基十只变化 %，下面小字「核心五通道 ±X%」；右侧按规则自动生成一句结论：
  - 宽基 < −10% 且行业 > 0 → 「宽基通道明显降温、行业 ETF 反而 +X%——托底的钱在收手，进攻的钱在换标的。但成交降温 ≠ 净赎回，方向要等份额回填才能定。」
  - 宽基 > +10% 且行业 < 0 → 资金向宽基集中，留意托底迹象
  - 两者都 > +10% → 整体活跃度上升
  - 两者都 < −10% → ETF 通道整体降温
  - 其余 → 变化不大
- 比值条：四组各一条，虚线 = 100%（持平），≥100% 红、<100% 绿，右侧显示 %
- 底注：「只有 XX 越过了 100%，其余全部低于 100%」或「四组全部低于 100%」

## 5. 页面设计

- 暖色纸面风：背景 `#f6f1ea`，卡片 `#fffdf9`，描边 `#ece3d6`，圆角 14px；标题前加 4px 红色竖条
- 主色：红 `#c8402f`、橙 `#e08a2a`、蓝 `#2f5d8a`、绿 `#2a9d75`、灰字 `#8a8178`
- 字体：`-apple-system, "PingFang SC", "Microsoft YaHei"`；数字用 `font-variant-numeric: tabular-nums`
- 布局顺序：页头（交易日 · 数据源 · 板块口径 · 尾盘来源 · 生成时间）→ 体温 → 浓度墙 → 资金流向 → 底部两栏（本轮净申赎 | 成交指纹）
- 响应式：≤900px 时 KPI 变两列、底部两栏改为单列；≤560px 时隐藏浓度条列；手机宽度 390px 下**不能出现横向滚动条**
- 窗口缩放时所有图表要 resize

## 6. 代码结构

```
market_dashboard/
  config.py      # 第 3 节全部可配置项
  sources.py     # TushareSource（单位换算 + 重试 + 降级）、OpenDTail
  demo.py        # DemoSource：方法签名与 TushareSource 完全一致，数据随机生成
  metrics.py     # 纯函数：净申赎、体温、浓度、成交指纹；不做 IO
  template.html  # 页面模板，占位符 /*__DATA__*/null 替换为 JSON
  build.py       # 命令行入口：取数 → 计算 → 渲染
  requirements.txt
  README.md      # 运行方法、每个面板的口径、积分 / 权限说明
```

要求：
- 数据源和计算分离，换数据源只需新增一个与 TushareSource 同接口的类
- 嵌入 HTML 的 JSON 里把 `</` 转义成 `<\/`；NaN 输出为 `null`，前端统一显示「—」
- 日志用 `logging`，INFO 级别打印每一步进度，WARNING 级别打印缺失数据和降级

## 7. 验收清单（逐条自检并报告结果）

1. `python build.py --demo` 能跑通，页面有模拟数据横幅，浏览器控制台无报错
2. 用真实 token 跑最新交易日，5 个面板都有数据；不可用的部分按第 2 节降级并在页面注明
3. 抽查：任选 1 只 ETF、1 个交易日，手工用 (份额差 × 收盘价) 复算净申赎，与页面数值一致
4. 抽查：任选 1 个板块，手工复算浓度，与页面一致
5. 「待披露」逻辑正确：深市份额未更新的那天显示「待披露」，不是 0
6. 桌面（1300px）和手机（390px）各截一张全页图；手机无横向滚动
7. 输出总结：成功的面板、降级的面板及原因、取不到数据的 ETF 代码、实际用到的接口及其所需积分

## 8. 不要做的事

- 不要编造数据或用模拟数据冒充真实数据；取不到就显示空值，并写明原因
- 不要把 token 写进任何文件
- 不要把 70%–90% 的归因比例写成事实，页面上必须注明是假设
- 不要为了让页面「好看」去填补缺失日期
- 「韭菜浓度」和「体温」是近似口径，在 README 中写明这一点，不要声称与原视频算法一致
